HOTELPRO: HOTEL MANAGEMENT SOLUTION

Project Description:

  • HotelPro is an end-to-end enterprise hotel management and reservation web application built using the modern MERN stack (MongoDB, Express.js, React.js, and Node.js) with secure JSON Web Token (JWT) role-based authentication and Bootstrap-powered luxury glassmorphic styling. The system streamlines hotel operations across independent boutique properties and large hospitality chains, providing real-time room inventory synchronization, interactive suite booking, automated 12% hospitality tax computations, multi-channel payment simulations with downloadable itemized invoices, automated room turnover dispatching to housekeeping staff upon guest checkout, and an executive analytics suite tracking live occupancy rates, Average Daily Rate (ADR), and comprehensive guest lifetime customer profiles.

Scenario:

In today’s fast-paced hospitality industry, managing hotel operations efficiently and securely is more crucial than ever. At HotelPro, we offer a reliable and intuitive hotel management system designed to meet the evolving needs of modern hospitality. Whether you're handling reservations, managing guest information, or processing payments, our platform ensures seamless operations with advanced security and scalability. HotelPro provides a robust backend infrastructure that powers efficient booking management, real-time availability tracking, and secure user authentication. We prioritize data privacy, encryption, and compliance, ensuring that every guest interaction is protected from unauthorized access. With a user-friendly interface and seamless integrations, our system simplifies hotel management for both independent properties and large hospitality chains.

● MVC Pattern

MVC Architecture Pattern

The backend application is designed using the Model-View-Controller (MVC) architectural pattern, a widely adopted software design approach that promotes separation of concerns by organizing the application into three distinct layers: Model, Controller, and View (Routing Layer). This architecture improves code organization, maintainability, scalability, and collaboration among development teams.

Model Layer (Data Layer)

The Model Layer is responsible for managing the application's data and business entities. It defines the structure, relationships, validation rules, and constraints for the data stored in the database.

In this project, the Model layer is implemented using Mongoose, an Object Data Modeling (ODM) library for MongoDB. Mongoose provides schema-based data modeling, enabling developers to define data structures and perform database operations efficiently.

The responsibilities of the Model layer include:

  • Defining database schemas and data models (User.js, Room.js, Booking.js, Task.js).
  • Managing relationships between collections.
  • Performing CRUD (Create, Read, Update, Delete) operations.
  • Applying data validation and business rules.
  • Interacting directly with the MongoDB database.

By centralizing data-related logic within the Model layer, the application ensures data consistency and simplifies database management.

Controller Layer (Business Logic Layer)

The Controller Layer acts as the bridge between incoming client requests and the application's data models. It contains the core business logic of the application and coordinates the flow of data between the routing layer and the database.

When a request is received, the controller:

  1. Accepts and processes the request data.
  2. Validates and transforms input where necessary.
  3. Invokes appropriate Model methods to perform database operations.
  4. Applies business rules and application logic.
  5. Formats and sends the appropriate response back to the client.

This separation ensures that business logic remains independent of routing and database implementation details, resulting in cleaner and more maintainable code.

View Layer (Routing Layer)

In a backend REST API application, there is typically no traditional View layer responsible for rendering user interfaces. Instead, the Routing Layer serves a similar role by defining API endpoints, receiving HTTP requests, and directing them to the appropriate controller functions. While it is not a true View in the classical MVC sense, it acts as the entry point for client interactions with the backend application.

The routing layer is responsible for:

  • Defining RESTful API endpoints.
  • Mapping HTTP methods (GET, POST, PUT, PATCH, DELETE) to controller functions.
  • Managing middleware execution such as authentication, authorization, validation, and logging.
  • Forwarding requests to the appropriate controllers.

This layer serves as the entry point for all client interactions with the backend system and ensures proper request handling and endpoint organization.

Request Flow in MVC Architecture

The typical request lifecycle within the application follows these steps:

  1. The client sends an HTTP request to a specific API endpoint.
  2. The Route receives the request and forwards it to the corresponding Controller.
  3. The Controller processes the request and invokes the necessary Model operations.
  1. The Model interacts with the MongoDB database and returns the requested data.
  2. The Controller formats the result and sends a response back through the Route.
  3. The client receives the final response.

This structured workflow ensures clear responsibilities and efficient communication between application layers.

● Steps for Project execution

Step 1: Set Up the Frontend (React App):

  • a) Open a terminal and navigate into the client folder: 
    cd frontend
  • b) Once installation is done, start the React development server: 
    npm run dev
  • c) The app should now be running on: http://localhost:5173

Step 2: Set Up the Backend (Express Server)

  • a) Open a new terminal tab/window or split the terminal.
  • b) Navigate into the server folder: 
    cd ../backend

Step 3: Configure Environment Variables

  • a) Inside the server folder, create a new file named .env (no file extension).
  • b) In that .env file, add your MongoDB connection string and JWT secret: 
    PORT=5000
MONGO_URI=mongodb://localhost:27017/hotelpro
JWT_SECRET=hotelpro_super_secure_jwt_secret_key_2026

Step 4: Start the Backend Server:

  • Inside the same server folder, run the backend server using: 
    node server.js
  • The server should start on: http://localhost:5000
